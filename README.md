# Student Support — Telegram AI companion

Частный прототип для поддержки студентов 18–21 года. Это AI-помощник, не психолог и не медицинская услуга. Работает только в личных сообщениях с пользователями из списка доступа.

## Что реализовано

- Выбор языка ответа моделью по последнему содержательному сообщению; явная просьба сменить язык имеет приоритет. Поддержка любого языка зависит от выбранной модели и требует проверки. Служебные сообщения: русский по Telegram locale, иначе английский.
- Согласие `/agree` с подтверждением 18+, `/privacy`, `/help`.
- Временный контекст: максимум 12 пар сообщений, очистка после 30 минут бездействия (фоновая проверка каждые 15 секунд) или перезапуска.
- `/new` очищает контекст; `/delete` очищает его и отзывает согласие. Уже отправленный API-запрос отменить этим нельзя; его ответ отбрасывается.
- Лимит длины сообщения, частоты запросов, количества сессий и параллелизма. Тексты сообщений и исключений не записываются в лог приложения.
- Инструкции модели о кризисных ситуациях, запрете диагнозов, выдуманных контактов и эмоциональной зависимости. Это инструкции, а не доказанная гарантия поведения.

## Запуск на Mac / Linux (Python 3.11+)

1. Создайте бота в https://t.me/BotFather командой `/newbot`. Сохраните токен локально. Отключите добавление в группы через `/setjoingroups`.
2. В каталоге проекта выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
chmod 600 .env
```

3. Заполните `.env`: токен Telegram, AI_PROVIDER, AI_API_KEY (для облачного провайдера), AI_MODEL и числовые Telegram ID тестировщиков через запятую. Никому не отправляйте ключи и не коммитьте `.env`.
4. Для определения своего ID отправьте боту `/start` и локально, до запуска бота, выполните:

```bash
python - <<'PY'
import asyncio, os
from dotenv import load_dotenv
from aiogram import Bot
async def show_ids():
    load_dotenv('.env')
    async with Bot(os.environ['TELEGRAM_BOT_TOKEN']) as bot:
        for update in await bot.get_updates():
            if update.message and update.message.from_user:
                u = update.message.from_user
                print(u.id, u.username)
asyncio.run(show_ids())
PY
```

Сверьте username со своим аккаунтом; не добавляйте неизвестные ID. При пустом выводе отправьте новое сообщение. Не запускайте одновременно несколько экземпляров бота. Если ранее был установлен webhook, его нужно снять перед polling.

5. Запустите:

```bash
python bot.py
```

6. В Telegram: `/start`, прочитайте условия, затем `/agree` и сообщение. Бот работает, пока процесс запущен. Для круглосуточной работы нужен постоянно работающий сервер; в этом проекте развёртывание не выполнено.

## Приватность и ограничения

Текст поступает в Telegram и выбранный AI backend. Для локальной Ollama генерация выполняется на вашем компьютере; для Groq/OpenAI текст отправляется соответствующему провайдеру. В режиме OpenAI Responses используется `store=False`, но это не обещание нулевого хранения провайдерами: https://developers.openai.com/api/docs/guides/your-data . Команды удаления очищают только память приложения, не чат Telegram или журналы провайдеров. Метаданные согласия также временные. Возраст подтверждается самим пользователем, документы не собираются.

Это частный пилот. Пока нет проверяемого справочника кризисных контактов, человеческого мониторинга, клинической валидации, дневника настроения, кнопок упражнений или постоянной базы. Бот не обещает найти местные службы: направляет к живому человеку/местной экстренной помощи без выдуманных номеров. Перед публичным запуском необходимы профессиональная проверка сценариев поддержки, оценка защиты данных и проверка поведения на каждом целевом языке. Задайте лимиты использования в API-проекте; локальные ограничения не являются гарантией бюджета.

## Проверка

```bash
python -m unittest -v
python -m compileall -q .
```

Автотесты проверяют изоляцию и границы памяти, отзыв согласия и Unicode-разбиение. Они не проверяют реальное качество поддержки. Проверки с живыми Telegram/OpenAI не выполнены: ключи не предоставлены.

Ручной пилот: отсутствие AI-запросов до согласия; RU→EN→кыргызский; смена языка по просьбе; `/delete` во время генерации; два разных пользователя; отказ API; сообщения о непосредственной опасности и неоднозначном отчаянии; отсутствие диагнозов/выдуманных телефонов. Не используйте реальные чувствительные данные в тестах.

## Бесплатный AI backend

По умолчанию выбран **локальный Ollama**, без оплаты AI-запросов. Установите Ollama с https://ollama.com , скачайте локальную (не cloud) текстовую модель через `ollama pull <model-tag>`, запустите `ollama serve`, если приложение ещё не подняло сервер. Укажите точный tag в AI_MODEL, оставьте AI_API_KEY пустым. Скорость и доступный размер модели зависят от RAM и оборудования; конкретная модель пока не подобрана. Не открывайте порт 11434 в интернет. Компьютер должен оставаться включённым; электричество и оборудование не бесплатны.

**Groq Free tier**: создайте API-ключ на https://console.groq.com , установите AI_PROVIDER=groq, AI_API_KEY=<your-key>, AI_MODEL=<available-model-id>. Лимиты зависят от модели и аккаунта: https://console.groq.com/docs/rate-limits . Оставайтесь на Free plan, если не хотите включать платное использование. Политика данных: https://console.groq.com/docs/your-data . Бесплатность не означает пригодность для психологической поддержки: качество и безопасность каждого языка нужно проверить на вымышленных сценариях.

Для OpenAI: AI_PROVIDER=openai, ваш AI_API_KEY и AI_MODEL. SDK openai используется также как совместимый клиент для Ollama/Groq; при выборе этих backend запросы не направляются в OpenAI.

Документация совместимости: https://docs.ollama.com/api/openai-compatibility и https://console.groq.com/docs/openai . Интеграции не запускались с живыми сервисами. Перед первым реальным пользователем проверьте условия выбранного провайдера и корректность уведомления о данных.
